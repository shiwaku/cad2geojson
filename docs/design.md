# 設計書: cad2geojson — CAD 図面を地図に正しく載せる

作成: 2026-10-12 / 改訂: 2026-10-12（dwg2geo を土台にする方針に変更） / 状態: **Phase 1 完了**（次は Phase 2）

## 1. 目的

CAD 図面（DWG / DXF）を、MapLibre GL JS などの Web 地図に**正しい位置で**重ねられる GeoJSON にする。

- 変換（DWG を読んで図形を取り出す）は既存の OSS [dwg2geo](https://github.com/milkway/dwg2geo) に任せる
- cad2geojson は、dwg2geo に無い **「地図に正しく載せる」部分**を作る。位置合わせ、図面の部分ごとの扱い、日本の座標系、DXF の文字コード
- ブラウザ版は**変換サーバーなし**で動かす（図面を外部に送らなくて済む）

背景は 2 つある。

1. 2024 年 4 月に顧客提供の DWG（平面直角座標系 9 系、mm 単位、AC1032）を GIS データ化したとき、AutoCAD で DXF に変換 → `ogr2ogr` → geopandas で座標を 0.001 倍、と 3 つの道具をまたいだ
2. 建設コンサルタントなど、CAD 図面を Web 地図に載せたい需要がある。ブラウザで DWG を読む手段（acadrust / LibreDWG の WASM 版）もこの夏に揃った

## 2. 方針: dwg2geo を土台にする

### 2.1 経緯

最初の設計（acadrust を直接使って一から作る）のあとに、ほぼ同じ目的の dwg2geo（MIT、v0.2.5）が見つかった。実在の建築図面で評価した結果（[eval-dwg2geo.md](eval-dwg2geo.md)）から、変換は dwg2geo に任せ、cad2geojson は足りない部分に絞ることにした。

### 2.2 dwg2geo に任せること（評価で確認済み）

| 項目 | 評価結果 |
|---|---|
| DWG の読み込み | ODA が書いた AC1032 / AC1015 の 6 ファイルを strict で読めた。形式による出力の差はハンドル以外なし |
| 図形の変換 | ブロック展開（入れ子・MINSERT・レイヤ 0 の継承）、BYLAYER / BYBLOCK の色・線種の解決、寸法、HATCH の穴あきポリゴン |
| 日本語 | TEXT / MTEXT の日本語が正しい（DWG の場合） |
| 未対応の扱い | 全エンティティの行き先をレポートに記録。未対応（WIPEOUT など）は理由つきで報告し、黙って捨てない |
| 相似変換の計算 | 対応点から最小二乗で解き、残差と RMS を出す |
| ブラウザ | npm パッケージ（WASM）。ライブラリ API `convert_bytes()` はバイト列から図面座標の GeoJSON を返し、ファイル I/O を持たない |

### 2.3 cad2geojson が作ること（評価で分かった不足）

| # | 不足 | 評価で起きたこと |
|---|---|---|
| 1 | **DXF を読めない** | `.dxf` を渡すと「Unsupported CAD version」。同じ図面を GDAL で読むと、R12（文字コード記録なし）は GeoJSON が壊れ、R2010 は文字化けした |
| 2 | **図面の一部ごとに位置合わせできない** | 1 枚に 1 階と 2 階が並ぶ図面で、1 階に合わせると 2 階が約 130 m ずれ、表題欄が道路に載った |
| 3 | **縮尺を固定できない** | CAD は縮尺が単位から確定しているのに、相似変換は縮尺も解く。2 点で解くと屋根の倒れ込みで 1.7% ずれた |
| 4 | **対応点を経緯度で渡すと歪む** | 地図側の座標のまま相似変換を解くため、経緯度だと東西が約 0.81 倍に潰れる |
| 5 | **ブラウザで座標系変換できない** | 座標系変換は PROJ（C ライブラリ）依存で、ビルド済みバイナリにも WASM 版にも無い |
| 6 | **文字の属性に位置合わせが反映されない** | 位置合わせ後も文字の回転角・文字高が図面の値のまま。文字の揃え位置も属性に無い |
| 7 | **対応点を探す手段が無い** | 一番手間がかかる。今回は図形の中心の自動抽出で済ませた |
| 8 | **`$MEASUREMENT` の読み違い** | mm 図面を english と報告。acadrust 0.5.1 固定が原因（Phase 0 で確認） |

### 2.4 不足の扱い: 上流に PR は送らず、cad2geojson の中で対処する

dwg2geo・acadrust の本家には PR を送らない。不足は cad2geojson の中で、上流の公開 API だけを使って補う。

| 不足 | 対処 |
|---|---|
| 1 DXF の入力 | acadrust 0.6 で DXF を読み、DWG（メモリ上）に書き出して dwg2geo の `convert_bytes()` に渡す（`crates/read`）。図形の取り出し方が DWG と同じになる。ビッグシップの DXF 3 枚で、ODA で変換した DWG と図形・レイヤ・文字列が一致した |
| 1 DXF の文字コード | `$DWGCODEPAGE` の無い R2007 より前の DXF は、中身が cp932 として妥当なら `ANSI_932` で読む。`--dxf-encoding` で指定もできる |
| 8 `$MEASUREMENT` | cad2geojson は縮尺を `--units` で明示して固定するので、位置合わせには影響しない |
| 6 文字の揃え位置 | 必要になったら cad2geojson 側で扱う（未対応） |
| 2・3・4・5・6（回転角・文字高）・7 | cad2geojson（位置合わせと地図表示の話） |

DXF の経路は acadrust を 2 つの版（dwg2geo が使う 0.5.1 と、DXF を読む 0.6.4）で持つ。0.5.1 は R12 の DXF を読めないため。acadrust の DWG の書き出しは元の版のまま書くので、R12 の DXF は R2000（AC1015）として書く（R12 形式の書き出しは Jw_cad の図面で失敗した）。

位置合わせは図面座標の GeoJSON を入力にするので、dwg2geo 以外（GDAL など）が出した GeoJSON でも動く。
## 3. 構成

```
                ┌──────────────────────────── cad2geojson ────────────────────────────┐
DWG ─┐          │                                                                  │
     ├─ dwg2geo ─┤→ 図面座標の GeoJSON ─→ ① 部分に分ける ─→ ② 位置合わせ ─→ ③ 座標系変換 ─┤→ GeoJSON（WGS84）
DXF ─┘ (convert │   ＋ レポート            （階・図枠）     （部分ごと）      （WGS84 へ）  │  ＋ 位置合わせの記録（JSON）
       _bytes)  │                                ↑                                 │
                │                          ④ 対応点を探す                            │
                └──────────────────────────────────────────────────────────────────┘
```

- **CLI**（Rust）: dwg2geo を crate として使う（`native-backend` 機能）
- **ブラウザ版**（Vite + MapLibre）: dwg2geo の npm（WASM）で変換し、cad2geojson の位置合わせを WASM で動かす
- cad2geojson の中核（①〜④）は **Rust の crate 1 つ**にまとめ、CLI と WASM で共有する。ファイル I/O は持たない

## 4. 部分に分ける（①）

1 枚の図面に複数の「部分」があるのは普通である。建築の平面図なら 1 階・2 階・図枠（表題欄）、土木なら平面図・縦断図・横断図が 1 枚に並ぶ。地図に載せるのは平面の部分だけで、部分ごとに位置が違う。

- **部分の定義**: 図面座標の範囲（矩形または多角形）、またはレイヤの集合。図形は外接矩形の中心で振り分ける（評価で使った方法）
- **自動の提案**: 図形の空間的なすき間で塊に分け（評価の図面では y = 50,000〜70,000 に図形の無い帯があった）、図枠らしい長方形（長い水平・垂直線で囲まれた領域）を見つけて、部分の候補として出す。確定は利用者が行う
- **地図に載せない部分**: 図枠・凡例・縦断図などは「載せない」と指定できる。出力しないか、図面座標のまま別ファイルに出す
- **部分どうしの関係**: 同じ建物の階どうしは、共通する図形（柱など）で相対位置が決まる。評価では柱 23 組の突き合わせで、1 階と 2 階の位置関係が残差中央値 23 mm で求まった。この関係を記録しておけば、**1 つの部分を位置合わせすれば他の部分も決まる**

## 5. 位置合わせ（②）

### 5.1 図面の種類

| 種類 | 例 | やること |
|---|---|---|
| 座標付き図面 | 測量図、公共測量の平面図 | CRS を指定し、単位を直すだけ |
| ローカル図面 | 建築平面図、詳細図 | 対応点などで地図上に配置する |

### 5.2 変換のモデル

| モデル | 求める値 | 最低点数 | 使いどころ |
|---|---|---:|---|
| **剛体＋固定縮尺（既定）** | 回転・平行移動（3） | 2 | 単位が分かっている図面。縮尺は単位から決める（mm なら 0.001） |
| 相似変換 | 回転・平行移動・一様な縮尺（4） | 2 | 単位が不明、または図面の縮尺を疑うとき |

アフィン変換や多項式は入れない。CAD 図面は縮尺が正確でゆがみがないはずで、自由度を上げると対応点の取り違えを吸収して気づけなくなる。

**既定を固定縮尺にする理由。** 評価で、大ホールとレストランの 2 点から相似変換を解くと、縮尺が 1.7% 小さく出た（高い屋根の倒れ込みで中心が寄って写るため）。単位から縮尺が分かるなら、それを固定したほうが正しい。固定縮尺と相似変換で縮尺がどれだけ違ったかは、図面の単位の誤りや対応点の偏りに気づく手がかりとして必ず表示する。

### 5.3 対応点と作業用の投影座標系

- 対応点の地図側は、**どの CRS で受け取っても、作業用の投影座標系に変換してから解く**。経緯度のまま回転・縮尺を解くと、東西と南北で 1 度の長さが違うため形が歪む（dwg2geo の不足 4）
- 作業用の投影座標系は日本なら平面直角座標系。系は**指定を必須にする**。経度から自動で選ぶと、系の境界付近で誤った系を選んでも気づきにくい。海外の検証データ用に UTM と RD New（オランダ）も持つ（測地系の差 1 m 未満は無視する。RD New だけは PROJ の既定と同じ 7 パラメータで WGS84 に変換する）
- 3 点以上なら最小二乗で解き、点ごとの残差・RMS・最大を出す。**対応点に使わない検証点**も受け取り、その誤差を別に出す（対応点の残差だけでは、点の取り方の誤りに気づけない）
- **X / Y の入れ替え**: 測量は X が北、CAD の X は右（東）。`--swap-xy` を用意し、座標付き図面で外接矩形を平面直角座標系の範囲と照らして、入れ替えたほうが妥当なら提案する

### 5.4 指定方法

```
対応点:      --gcp gcp.csv        # part,cad_x,cad_y,map_x,map_y[,role]  role = control | check
             --gcp-crs EPSG:4326  # 地図側の CRS（何でもよい）
基準点＋回転: --anchor-cad x,y --anchor-map x,y --rotation deg
作業用:      --work-crs EPSG:6673
縮尺:        --scale fixed（既定。単位から） | free（相似変換）
```

位置合わせの結果（部分ごとの変換、部分どうしの関係、対応点、残差、検証点の誤差）は JSON に書き出し、同じ JSON を入力に渡せば同じ結果を再現できるようにする。ブラウザ版で目で合わせ、CLI で同じ種類の図面を一括変換する、という使い方ができる。

## 6. 座標系変換と出力（③）

- 座標系変換は純 Rust の [proj4rs](https://github.com/3liz/proj4rs) を使う。ブラウザ版でも同じものが WASM で動く（dwg2geo の不足 5）
- 平面直角座標系（JGD2011, EPSG:6669〜6687 / JGD2000, EPSG:2443〜2461）の定義は表として持ち、EPSG データベースは同梱しない
- JGD2011 → WGS84 は同一とみなす（Web 地図の表示では問題にならない）
- 出力は **GeoJSON / GeoJSONSeq（WGS84、RFC 7946）だけ**。投影座標系での出力（FlatGeobuf など）は持たない。経緯度を倍精度で持てば mm 以下まで表せ、平面直角座標系が要るなら QGIS などで変換し直せばよい
- **文字の属性を位置合わせに合わせて直す**（dwg2geo の不足 6）: `text_rotation_deg` に位置合わせの回転を足して真北基準にし、`text_height` に縮尺を掛けて地上の m にする。元の値も残す
- PMTiles は tippecanoe で作る手順を README に書く

## 7. 対応点を探す（④）

評価で一番手間がかかったのがここだった。段階的に用意する。

| 段階 | 方法 | 評価での実績 |
|---|---|---|
| 1 | **地図と図面を並べて点を打つ画面**（ブラウザ版） | ― |
| 2 | **図形の中心を自動抽出して候補にする**: 図面側は円・楕円・長方形の外壁、地図側は航空写真から明るい屋根の領域を抜き出して円・楕円を当てはめる。中心を使えば屋根の張り出しの影響が打ち消される | 円形レストランと大ホールの中心で、独立な向きの検証と 0.16〜0.41° 一致 |
| 3 | 地図側の建物外形（基盤地図情報、PLATEAU）との形の照合 | 楕円の当てはめはできたが、基準の精度（地図情報レベル 2500）と点の独立性が足りず、回転が約 0.9° ずれた |

チャンファーマッチング（図面の線と写真のエッジの距離最小化）は評価で安定しなかった（写真に図面に無いエッジが多い）ので採らない。

## 9. 入力について

### 9.1 DWG の仕様は公開されていない

DWG は Autodesk の独自バイナリ形式で、仕様は公開されていない。公式に読み書きできるのは Autodesk 製品と、同社の有償 SDK（RealDWG）のライセンス製品である。OSS が DWG を読めるのは、Open Design Alliance（ODA）が解析結果を「Open Design Specification for .dwg files」として無料公開しているなど、リバースエンジニアリングの蓄積があるためだ。DXF は Autodesk が仕様（DXF Reference）を公開している。

- DWG は完全に読める保証がない。実際の CAD ソフトが書き出した DWG で検証する
- 読めない DWG は、ODA File Converter（無料）で DXF に変換してから読む経路を案内する（自動で呼ぶかは ODA の利用条件を確認してから）
- 「DWG」の名称は Autodesk との商標問題の経緯があるため、「DWG ファイルを読み込める」という説明的な表現にとどめる

### 9.2 日本の DXF でよく出会うもの

- **Jw_cad から書き出した R12 の DXF**: 日本では Jw_cad（無料）が設計事務所・設備業者・工務店で広く使われ、受け渡しは DXF で書き出される。評価の全体平面図もこれと思われる（レイヤ名が `_0-0_0` の形式）。**単位も文字コードも記録が無い**（中身は cp932、実寸の mm）。GDAL が GeoJSON を壊したのもこの形式で、最優先で扱う
- **R2007 以降の DXF**: 文字列は UTF-8 だが、ヘッダの `$DWGCODEPAGE` が `ANSI_932` のままのことがある。ヘッダを信じて cp932 として読むと文字化けする（GDAL がこれだった）。形式の世代で判断する
- MTEXT の書式コード（`\P` 改行、`\f...;` フォント、`{\C1;...}` 色など）は除いてプレーンテキストにする。`%%c`（φ）、`%%d`（°）、`%%p`（±）は記号に置き換える
- cp932 の `0x817C`（長音の代わりに使われがちな「－」）は U+FF0D にする（Windows で作られた図面の扱いに合わせる）

### 9.3 単位

- `$INSUNITS` が 0（単位なし）で指定も無ければ**エラーにする**。黙って m とみなすと、mm 図面が 1000 倍の大きさになる
- 単位の記録が無い図面では、スケールバーの長さ（評価の全体平面図は「10m」の線がちょうど 10,000）や、座標値の桁から単位を推定し、**提案として表示するだけ**にする

## 11. リポジトリ構成

```
cad2geojson/
├─ Cargo.toml              workspace
├─ crates/
│  ├─ core/                部分分け・位置合わせ・座標系変換・文字の属性の補正（I/O なし）
│  ├─ read/                DWG / DXF → 図面座標の GeoJSON（dwg2geo・acadrust）
│  ├─ cli/                 clap。read で読み、core に渡す
│  └─ wasm/                wasm-bindgen。core をブラウザ向けに公開
├─ web/                    Vite + MapLibre（pnpm）。dwg2geo の npm（WASM）を使う
├─ testdata/               取得したデータ（README.md 以外は追跡しない）
└─ docs/
```

- Rust は edition 2024。dwg2geo はマイナーバージョンを固定する（2026-10-12 時点 0.2.5）
- 開発環境は Windows 11（Rust 1.99.0 MSVC、VS Build Tools 導入済み）。Git Bash では `/usr/bin/link` が MSVC の `link.exe` より先に見つかるため、cargo は PowerShell から実行する。pnpm のスクリプトは `pnpm exec` で直接呼ぶ

## 12. リスク

| 項目 | 影響 | 対応 |
|---|---|---|
| dwg2geo が個人の若いプロジェクト（0.x） | 更新が止まる、破壊的変更 | バージョン固定。MIT なので、止まったらフォークできる。cad2geojson の位置合わせは図面座標の GeoJSON を入力にし、変換器に依存しない |
| 上流に PR を送らない方針 | 上流の不足が直らない | cad2geojson の中で上流の公開 API だけを使って補う（§2.4） |
| DWG の仕様が非公開 | 新しい形式・珍しいエンティティが欠ける | 本物の AutoCAD の DWG で検証。DXF 版との一致で検出 |
| 対応点の取り方で精度が決まる | 位置合わせの誤差 | 検証点と、独立な量（向きなど）での確認を仕組みに入れる。対応点の残差だけで判断しない |
| 航空写真の屋根の倒れ込み | 高い建物で数十 cm〜1 m の偏り | 低い建物を優先し、縮尺を固定する |
| 大きな図面をブラウザで読むとメモリが足りない | ブラウザ版が落ちる | Worker で処理し、上限を超えたら CLI を案内 |
| 実データの利用条件 | 検証データとして公開できない | 第三者の図面はリポジトリにも公開デモにも入れない。業務の貸与データは使わない |
